# Architecture Decision Records (ADRs)

* **ADR-001 (Monorepo Structure):** Tổ chức thành `apps/orchestrator`, `apps/studio-web` và `apps/media-engine`. `packages/contracts` là package legacy trong giai đoạn chuyển đổi và đã được xóa ở PR #60 sau khi frontend chuyển các consumer hiện có sang generated OpenAPI types và audit xác nhận không còn import.
* **ADR-002 (Queue Engine):** Chọn `ARQ` (AsyncIO Redis Queue) thay vì Celery để đồng bộ hoàn toàn với FastAPI + SQLAlchemy Async và hỗ trợ `defer_by` non-blocking polling.
* **ADR-003 (State Orthogonalization):** Tách biệt 4 trạng thái độc lập: `ShotApprovalState`, `ShotGenerationState`, `NodeExecutionState`, `ConnectionHealthState`.
* **ADR-004 (Secret Vault & Redaction):** Mã hoá API key bằng Fernet (`SECRET_ENCRYPTION_KEY`); lọc bỏ mọi key/cookie/proxy password khỏi log và response.
* **ADR-005 (Frame Chaining):** Dùng FFmpeg tách frame đầu/cuối tự động để nối mượt các shot liên tiếp.
* **ADR-006 (Frontend Stack):** `apps/studio-web` dùng Tailwind CSS v4 + shadcn/ui (Radix) + lucide-react cho giao diện, TanStack Query v5 cho server state, Zustand v5 cho client state, TanStack Router v1 cho điều hướng/URL state, react-hook-form + zod cho form, @xyflow/react v12 cho workflow canvas; React giữ ở 18. Phương án đã cân nhắc: Mantine (ít cấu hình hơn nhưng hệ sinh thái/agent quen thuộc hẹp hơn và khó tuỳ biến sâu bằng token) và CSS viết tay như hiện trạng (đã chứng minh không scale được: không design token, không component chuẩn). Hệ quả: phải thêm ESLint/Prettier và `package-lock.json` cho frontend (Phase 0) và mọi agent làm frontend đều bị ràng bởi chuẩn này. Chuẩn đầy đủ: `docs/FRONTEND_ARCHITECTURE.md`.
* **ADR-007 (Generated API Contracts):** Frontend API types được sinh tự động từ OpenAPI schema của orchestrator bằng `openapi-typescript`, từ snapshot tại `apps/orchestrator/openapi.json` vào `apps/studio-web/src/lib/api/schema.d.ts`. Script `scripts/export_openapi.py`, snapshot, generated TypeScript và CI drift checks đã được triển khai ở Phase 0b. PRs #56–#59 typed các backend routers và làm sạch OpenAPI response schemas. PR #60 bắt đầu consumer migration bằng việc suy kiểu successful JSON response theo path/method từ generated `paths`, đồng thời chuyển các query consumer hiện có sang schema đó; các consumer cho feature mới phải tiếp tục pattern này. Package `packages/contracts` được xóa ở PR #60 sau khi rà soát source TypeScript/JavaScript và xác minh không còn import; bốn union cũ có schema generated tương ứng. Phương án đã cân nhắc và bị loại là nới Docker build context lên root monorepo để tiếp tục dùng contracts viết tay — cách này giữ lại nguồn drift và trói image web vào layout của monorepo. PR #42 (`feat/studio-web-workspace`) đã đóng mà không merge; phạm vi yêu cầu của nhánh đó vẫn là đầu vào cho Phase 1–2 nhưng mã của nhánh đó không làm nền. Hệ quả: endpoint backend phải khai báo `response_model` để OpenAPI sinh type tốt, và mọi API consumer mới phải dùng generated types thay vì khai báo contract viết tay.

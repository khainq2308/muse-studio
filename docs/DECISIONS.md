# Architecture Decision Records (ADRs)

* **ADR-001 (Monorepo Structure):** Tổ chức thành `apps/orchestrator`, `apps/studio-web`, `apps/media-engine`, và `packages/contracts` (legacy/transitional, đóng băng và chỉ giữ tới khi generated OpenAPI types thay thế mọi consumer).
* **ADR-002 (Queue Engine):** Chọn `ARQ` (AsyncIO Redis Queue) thay vì Celery để đồng bộ hoàn toàn với FastAPI + SQLAlchemy Async và hỗ trợ `defer_by` non-blocking polling.
* **ADR-003 (State Orthogonalization):** Tách biệt 4 trạng thái độc lập: `ShotApprovalState`, `ShotGenerationState`, `NodeExecutionState`, `ConnectionHealthState`.
* **ADR-004 (Secret Vault & Redaction):** Mã hoá API key bằng Fernet (`SECRET_ENCRYPTION_KEY`); lọc bỏ mọi key/cookie/proxy password khỏi log và response.
* **ADR-005 (Frame Chaining):** Dùng FFmpeg tách frame đầu/cuối tự động để nối mượt các shot liên tiếp.
* **ADR-006 (Frontend Stack):** `apps/studio-web` dùng Tailwind CSS v4 + shadcn/ui (Radix) + lucide-react cho giao diện, TanStack Query v5 cho server state, Zustand v5 cho client state, TanStack Router v1 cho điều hướng/URL state, react-hook-form + zod cho form, @xyflow/react v12 cho workflow canvas; React giữ ở 18. Phương án đã cân nhắc: Mantine (ít cấu hình hơn nhưng hệ sinh thái/agent quen thuộc hẹp hơn và khó tuỳ biến sâu bằng token) và CSS viết tay như hiện trạng (đã chứng minh không scale được: không design token, không component chuẩn). Hệ quả: phải thêm ESLint/Prettier và `package-lock.json` cho frontend (Phase 0) và mọi agent làm frontend đều bị ràng bởi chuẩn này. Chuẩn đầy đủ: `docs/FRONTEND_ARCHITECTURE.md`.
* **ADR-007 (Generated API Contracts):** Type của frontend được sinh tự động từ OpenAPI schema của orchestrator (openapi-typescript, từ snapshot OpenAPI dự kiến đặt tại apps/orchestrator/openapi.json; snapshot và script export offline dự kiến scripts/export_openapi.py sẽ được tạo ở Phase 0, hiện chưa có; CI phải chống drift) vào trong `apps/studio-web/src/lib/api/`; ngừng import mới; chỉ loại bỏ `packages/contracts` ở bước cuối Phase 0c, sau khi mọi consumer đã chuyển sang generated types và test/build chứng minh không còn import cũ. Phương án đã cân nhắc và bị loại là nới Docker build context lên root monorepo để tiếp tục dùng contracts viết tay trong `packages/contracts` — cách này giữ lại nguồn drift (type viết tay trôi khỏi API thật) và trói image của web vào layout của cả monorepo, trong khi types sinh tự động xử lý cả hai vấn đề. PR #42 (`feat/studio-web-workspace`) đã đóng mà không merge; đây là ví dụ lịch sử cho phương án không được chọn. Phạm vi chức năng của PR đó vẫn là đầu vào yêu cầu cho Phase 1–2, nhưng mã của nhánh đó không làm nền. Hệ quả: các endpoint backend phải khai báo `response_model` mới sinh type tốt, nên Phase 0 gồm audit và bổ sung `response_model` ở backend.

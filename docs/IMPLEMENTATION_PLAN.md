# Implementation Plan & Milestones

* **M0 (Completed):** Repo audit, Capability Matrix, DAG Engine, Prompt Compiler/Linter, Secret Redactor, Contract Tests.
* **M1 (Completed):** Project CRUD + Revisions, Encrypted Connection Profiles + Capability Probe, Safe Asset Storage, Studio Web M1 Dashboard.
* **M2 (Partial):** Script parser/backend primitives, Script & Story Bible UI (`?view=script|bible`, script import with overwrite guard, draft `ScriptRevision` listing and review-before-apply via `GET /api/v1/projects/{project_id}/script-revisions` and `POST /api/v1/projects/{project_id}/script-revisions/{revision_id}/apply`, Story Bible CRUD, reference asset upload/lazy preview, missing character reference attention banner, shot list JSON/CSV export) and Shot Board Master–Detail workspace (`?shot=&tab=`, scene/shot navigator rail with real-field filters, shot edit via `PATCH` with inline 422 errors and recompiled prompt, take review with `created_at` timestamps, A/B compare, take selection, continuity flags, authenticated frame/video previews, non-blocking predecessor-order warning and live queue status) are implemented and tested with unit/integration tests and Playwright against a mocked API. On 2026-10-23 Shot Board take review was also exercised in Chromium (Playwright script) against a real local stack (uvicorn API + real ARQ worker + Redis + SQLite, mock provider connection, no paid provider): take list with authenticated frame thumbnails, A/B compare of two real takes, selecting take 2 re-pointed the frame-chained Shot 2 (backend set it to `not_started` on the new frame), and flag continuity with regenerate created task `tsk_82db1ed740` (priority 80) that the worker completed as a new take, with no API errors. Remaining before completion: real-stack browser verification of Script & Story Bible and real provider (muse.ai) video playback.
* **M3 (Partial):** DAG validation/planning/cache primitives, workflow persistence (`GET`/`POST` project workflows, `GET` by workflow ID, `PUT` graph, `PATCH` layout) and the React Flow workflow canvas (`dry_run` default, confirmed `full` run, `from_here`/`downstream` partial runs, inline manual-gate approval, serialized layout saves and automatic reload of the active workflow) exist; execution run history is session-scoped and production node executors remain simulated.
* **M4 (Partial):** Queue/polling, the Queue Monitor UI (including operator questions), Shot Board live task activity/latest-generation status and the ARQ worker wiring are implemented; `enqueue_shot_generation` replays the newest attempt of a request after forced retries (`<base>_retry_<6 hex>`), the `arq-e2e` CI job verifies enqueue → worker dispatch/poll → take, schedule-token dedupe, cancel, needs-input reply and recovery-cron re-scheduling with real Redis and separate API/worker processes, and a manual run against a real muse.ai account succeeded (docs/evidence/m4/2026-10-23-real-arq-worker.md). Remaining before completion: a real worker on PostgreSQL and worker crash/restart mid-task.
* **M5 (Partial):** Batch/take concepts exist; the Shot Board can enqueue a single shot, start a confirmed new attempt (`force_retry: true`) after an ended task, and launch a confirmed batch showing `frame_chain_continuity_not_guaranteed` warnings and blocked shots (mocked-API unit/Playwright tests only). The Shot Board UI lists takes with `created_at` timestamps, compares two takes A/B via `compare-takes`, selects a take (showing the new last frame and re-pointed downstream shots) and flags continuity with an optional confirmed regeneration (mocked-API unit/Playwright tests plus the 2026-10-23 real local stack run with the mock provider described under M2; uncertain regenerate failures are reported as an unknown outcome because the backend saves the flag before a `force_retry` enqueue). Take selection returns 404 unless the take belongs to the shot and to the shot's project. Frame chaining must still use real, validated boundary-frame PNG assets and pass an integration test.
* **M6 (Partial):** Backend FFmpeg export supports `hard_cut` and `cross_dissolve` transitions (with pinned `concat` output timebase before `xfade`) and silent AAC output; Timeline & Export UI supports sequence assembly, local clip editing (reorder via dnd-kit/keyboard, trim start/end, per-clip transition, gap before clip, remove and save via `custom_clips` with subtitle-loss confirmation), pre-export disclosure of rendered vs. unrendered features, and export job polling/MP4 download (unit/Playwright tests + backend FFmpeg render tests). Clip audio, title cards, subtitle burn-in/embedding and extra audio tracks remain unrendered by the backend exporter.
* **M7 (Partial):** Workspace-level `System & maintenance` (`/system`: observability metrics, backup restore, orphan scan/dry-run/cleanup, asset deletion by ID, system logs) and project-scoped `Project Settings` (`settings`: profile, revisions, duplicate, project backups, reference asset upload, project logs) exist and are tested against a mocked API; full production readiness requires acceptance evidence for accounts/proxies, workers, cleanup and end-to-end operations.

## Verification policy

scripts/audit_roadmap.py reports heuristic navigation signals, not behavior. scripts/check_docs_sync.py validates that each milestone has one explicit, allowed status and that capability-matrix status labels use the approved vocabulary; it deliberately does not infer completion from file names or dependencies. A milestone is complete only after implementation, acceptance tests and relevant runtime evidence are reviewed.

# Implementation Plan & Milestones

* **M0 (Completed):** Repo audit, Capability Matrix, DAG Engine, Prompt Compiler/Linter, Secret Redactor, Contract Tests.
* **M1 (Completed):** Project CRUD + Revisions, Encrypted Connection Profiles + Capability Probe, Safe Asset Storage, Studio Web M1 Dashboard.
* **M2 (Partial):** Script parser/backend primitives exist. Studio Web Shot Board part A (shot list grouped by scene, shot edit via `PATCH` with inline 422 errors and the recompiled prompt) is implemented and tested with unit tests and Playwright against a mocked API only; Shot Board part B (take review, A/B compare, take selection, continuity flags, authenticated frame/video previews and a non-blocking predecessor-order warning) is implemented and tested the same way (unit/integration tests and Playwright against a mocked API). On 2026-10-23 the branch was also exercised in Chromium (Playwright script) against a real local stack (uvicorn API + real ARQ worker + Redis + SQLite, mock provider connection, no paid provider): take list with authenticated frame thumbnails, A/B compare of two real takes, selecting take 2 re-pointed the frame-chained Shot 2 (backend set it to `not_started` on the new frame), and flag continuity with regenerate created task `tsk_82db1ed740` (priority 80) that the worker completed as a new take, with no API errors (evidence collected by the coordinating agent). Real provider (muse.ai) video playback was not tested. Script Studio and Story Bible are incomplete.
* **M3 (Partial):** DAG validation/planning/cache primitives exist; the React Flow workflow canvas and production node executors are incomplete.
* **M4 (Partial):** Queue/polling, the Queue Monitor UI (including operator questions) and the ARQ worker wiring are implemented; the `arq-e2e` CI job verifies enqueue → worker dispatch/poll → take, schedule-token dedupe, cancel, needs-input reply and recovery-cron re-scheduling with real Redis and separate API/worker processes, and a manual run against a real muse.ai account succeeded (docs/evidence/m4/2026-10-23-real-arq-worker.md). Remaining before completion: a real worker on PostgreSQL and worker crash/restart mid-task.
* **M5 (Partial):** Batch/take concepts exist; the Shot Board can enqueue a single shot and launch a confirmed batch, showing `frame_chain_continuity_not_guaranteed` warnings and blocked shots (mocked-API unit/Playwright tests only). The Shot Board UI can also list takes, compare two takes A/B via `compare-takes`, select a take (showing the new last frame and re-pointed downstream shots) and flag continuity with an optional confirmed regeneration (mocked-API unit/Playwright tests plus the 2026-10-23 real local stack run with the mock provider described under M2; uncertain regenerate failures are reported as an unknown outcome because the backend saves the flag before a `force_retry` enqueue; the take API exposes no creation timestamp). Frame chaining must still use real, validated boundary-frame PNG assets and pass an integration test.
* **M6 (Partial):** Backend FFmpeg export supports a subset of transitions; Timeline Editor UI, clip audio, title cards, subtitles and extra audio tracks are incomplete.
* **M7 (Partial):** Some operations/backup/observability slices exist; full production readiness requires acceptance evidence for accounts/proxies, workers, cleanup and end-to-end operations.

## Verification policy

scripts/audit_roadmap.py reports heuristic navigation signals, not behavior. scripts/check_docs_sync.py validates that each milestone has one explicit, allowed status and that capability-matrix status labels use the approved vocabulary; it deliberately does not infer completion from file names or dependencies. A milestone is complete only after implementation, acceptance tests and relevant runtime evidence are reviewed.
